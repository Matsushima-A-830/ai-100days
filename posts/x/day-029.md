# Day 029 X投稿案

対象: [Panniantong/Agent-Reach](https://github.com/Panniantong/Agent-Reach)(MIT、AIエージェント向けネット接続CLI)。
検証: ログイン不要チャンネル(GitHub/V2EX/Bilibili)の実動作確認、GitHub issueページでのBefore/After比較、READMEのコマンド文法とヘルプ文言の実装との食い違いを実機で確認した。

## パターンA: 要点訴求型

AIエージェントにログイン不要でGitHub/YouTube/Bilibili/V2EXへのアクセスを与えるCLI「Agent-Reach」を実際に動かしてみた。

GitHubのissueページは素のcurlでは本文すら読めないが、Agent-Reach経由ではissue本文をクリーンなテキストとして確実に読めた。

https://github.com/Panniantong/Agent-Reach

## パターンB: 驚き訴求型

READMEのQuick Startに書かれているコマンドをそのまま打ったら`unknown command or channel: get`で失敗した。

READMEにある`get`という動詞は実在せず、正しくは`agent-reach <channel> <action>`。さらにヘルプが「コメント付きで読む」と説明している機能も、実際に返るのはコメント**件数**だけでコメント本文は取得できなかった。公式ドキュメントを鵜呑みにせず実行して初めて分かったギャップ。

https://github.com/Panniantong/Agent-Reach

## パターンC: 技術者向け詳細型

Agent-Reach(MIT)をローカルPCで実機検証。

- `uv tool install <GitHub Release zip>`で一発インストール成功(クラウド実行環境では3方法ともブロックされていた)
- `agent-reach github read yt-dlp/yt-dlp`・`v2ex hot`・`bilibili search "大模型"`はログイン不要で実際に動作
- GitHub issue(yt-dlp/yt-dlp#6539)を`agent-reach github read <issue URL>`で読み取り。素のcurlはReact SPAのシェルしか返さない
- READMEの`agent-reach get github read ...`は`BAD_INPUT`で失敗。正しい文法は`get`無し。issue参照も`owner/repo#N`では失敗しフルURLが必要
- ヘルプの「issue / PR (with comments)」は実際にはコメント件数(`raw.comments`が整数)のみを返す
- `youtube subtitle`はYouTube側のHTTP 429レート制限に実機で遭遇

https://github.com/Panniantong/Agent-Reach
