## 1. 要点訴求型

GitHub Trendingで急伸中の「REA」(エージェントにアプリをリバースエンジニアリングさせるMCPサーバー)を、自作Electronアプリ(割引ロジック+隠しデバッグ機能つき)で検証しました。

結果: IPC配線やAPI公開範囲の再構築は完全に正確。ただし「なぜ隠し機能なのか」の説明は自動では出ず、Evidenceを自分で読む一手が必要でした。

https://github.com/morluto/rea

## 2. 驚き訴求型

「Reverse Engineer Anything」を名乗るMCPサーバーREAに、自分で仕込んだ隠しデバッグ機能(特定の環境変数でのみ有効)を見つけさせようとしたら──

事実(Evidence)は最初の解析で既に取れていたのに、「なぜ隠し機能か」を1文で説明する機能は無く、自分で読み解く必要がありました。

検証の詳細↓
https://github.com/morluto/rea

## 3. 技術者向け詳細型

REA(npm: rea-agents@5.0.0, MIT)の`analyze-javascript-application`と`trace_application_feature`を、自作Electronアプリに対して検証しました。

- 構造再構築(BrowserWindow数・contextBridge API・IPCハンドラー数)は全項目で正解と一致
- `trace_application_feature`はIPCチャンネル名(文字列リテラル)なら正確に追跡できるが、識別子名(関数名・プロパティ名)をseedにすると"no-match"
- `recover-javascript-sources`は外部ツール(Wakaru)が別途必要で今回未インストールのため失敗

入力JSONの形式はドキュメント化されておらず、バリデーションエラーのレスポンスから復元しました。

https://github.com/morluto/rea

## 追記: 2つの失敗、両方とも解決しました

### 追記1(要点訴求型)

記事で報告した2つの失敗(識別子検索の"no-match"・Wakaru未導入)、
どちらも実際に解決策を試して解消できました。
原因はREAの欠陥ではなく、ドキュメントに書かれていない運用上の前提でした。
#AI100日チャレンジ #OSS検証

### 追記2(技術者向け詳細型)

- "no-match"問題: `function_node_id`(jsrg_node_*)ではなく`application_node_ids`の
  `jag_node_*`をnode-idシードに渡すと解決。文字列検索と同じ28ノード・43エッジを識別子起点で再構築できた
- Wakaru未導入問題: `npm install wakaru@1.13.0`→`REA_WAKARU_COMMAND`に絶対パス設定で解決。
  ただし単一バンドルファイルが必要でディレクトリは不可だった
- experiments/day-010/package.jsonにpinして再現可能な形に実装済み
