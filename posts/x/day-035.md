# Day 035 X投稿案

対象: Claude Code Game Studios (https://github.com/Donchitos/Claude-Code-Game-Studios, MIT)

## パターンA: 要点訴求型

Claude Codeを49エージェント・74スキルの「ゲーム開発スタジオ」に変えるOSSテンプレートを検証した。

- agents 49・rules 14はREADMEと完全一致
- hooksは実ファイル18、でもsettings.jsonに登録されてるのはちょうど15個(残りは共有ヘルパー)
- 肝心の`/start`実行はこちらの実行環境側の制約で止まり、ローカル検証に持ち越し

## パターンB: 驚き訴求型

ゲーム開発テンプレートを検証するはずが、途中でClaude Code自体の挙動に気づいてそちらが本題になった。

クローンしたテンプレートのディレクトリに`cd`しただけで、そのテンプレート自身の`CLAUDE.md`(「書き込み前に必ず確認を取れ」等のルール入り)が、何もReadしていないのに自分のセッションの指示として自動的に読み込まれていた。

`claude --help`で確認したら"CLAUDE.md auto-discovery"という正式機能だった。他人のテンプレートを調べるときは要注意。

## パターンC: 技術者向け詳細型

Claude Code Game Studios(MIT, 49 agents/74 skills/15 hooks/14 rules)を検証。

構造面はファイル数で裏取り→ほぼREADME通り(templates数だけ63 vs 62表記で1件ずれ)。

本題: `.claude/hooks/validate-write.sh`をPreToolUse相当のJSONで直接叩いても、`claude -p "/start" --dangerously-skip-permissions`で叩いても、こちらの実行環境の自動モード分類器に`[Code from External]`/`[Create Unsafe Agents]`で拒否された。クローン先のCLAUDE.md(@importも含む)は読み込まれるのに、クローン先のコード実行は別レイヤーでブロックされる、という非対称な挙動が面白かった。
