# Day 058 X投稿案

対象: OpenSRE (Tracer-Cloud) — https://github.com/Tracer-Cloud/opensre
記事: articles/day-058-opensre-ollama-cli-crash.md

## パターンA: 要点訴求型

CIが落ちた理由をAIが調べて直してくれるOSS「OpenSRE」を、有料APIキー無しで動かせるか試した。

結果: pip install一発で入るが、何も設定しないとデフォルトがAnthropicキー必須になっていて生のスタックトレースでクラッシュする。`LLM_PROVIDER=ollama`を足すだけで挙動が変わり、クラッシュせず本物のエージェントパイプラインまで動くことを確認した。

https://github.com/Tracer-Cloud/opensre

## パターンB: 驚き訴求型

「有料キー不要・ローカルLLMで動く」と書いてあるOSSを、本当に無料で動かそうとしたら何が起きるか試した。

→ 何も設定しない状態でRCA調査コマンドを叩くと、デフォルトのLLMプロバイダがAnthropicになっていて、親切なエラーメッセージ無しに生のPythonスタックトレースでそのまま落ちた。環境変数を1つ足すだけで挙動が一変するのを実際に確認できたのは面白かった。

## パターンC: 技術者向け詳細型

OpenSRE(Apache-2.0, PyPI版2026.4.5)を検証。

- `LLM_PROVIDER`未設定 → デフォルトは`anthropic`。`ANTHROPIC_API_KEY`無しだと`pydantic.ValidationError`が未処理のまま伝播してCLIがクラッシュする
- `LLM_PROVIDER=ollama`を指定 → クラッシュせずLangGraphの`plan_actions`ノードまで到達し、Ollama未起動のため`RuntimeError: LLM API request failed after multiple retries`で終了
- `config/llm_auth/provider_catalog.py`を読むと、Ollamaだけ`credential_kind=LOCAL`(鍵不要・到達性のみ)で他は`API_KEY`
- Ollama自体の起動とCI障害の実調査デモはローカル検証に持ち越し

https://github.com/Tracer-Cloud/opensre
