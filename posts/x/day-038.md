# Day 038 X投稿案

対象: NVIDIA Nemotron Labs/Dory1.0-4B (https://huggingface.co/papers/2611.03998, OpenMDW-1.1)

## パターンA: 要点訴求型

NVIDIAの新モデル「Dory1.0-4B」は、同じ重みのままループ回数(1〜4回)を切り替えて推論時の精度と計算量をトレードオフできる4Bモデル。
モデルカードのサンプルコードをそのまま試したら、`transformers`(PyPI安定版5.22.1)でも素の`llama.cpp`でも、どちらも`dory`アーキテクチャ未対応で実際に動かなかった。
GPU不足ではなく、推論エコシステム側の対応がまだ追いついていないという話。
検証詳細はZennに書いた。

https://huggingface.co/papers/2611.03998

## パターンB: 驚き訴求型

「公式モデルカードのコードをコピペすれば動く」と思ったら、2つの経路(transformers・llama.cpp)がどちらも同じ理由でエラーになった。

```
ValueError: ... model type `dory` ... does not recognize this architecture
llama_model_load: error loading model: unknown model architecture: 'dory'
```

GGUFファイルのSHA-256は公式値と完全一致、ファイル自体は壊れていない。
論文公開直後のモデルを動かそうとすると実際にはこういうことが起きる、という記録。

https://huggingface.co/papers/2611.03998

## パターンC: 技術者向け詳細型

NVIDIA Dory1.0-4B(DoryForCausalLM, OpenMDW-1.1)を検証。
`config.json`実測: n_input_layers=16/n_recurrent_layers=40/n_output_layers=16(サブレイヤー数、ブロック換算で8+20+8)。
`pip install "transformers>=4.57"`(5.22.1)→`AutoConfig.from_pretrained`は`ValueError: model type \`dory\` ... does not recognize this architecture`。
`pip install llama-cpp-python`(素のllama.cpp)でGGUF(sha256: 96080be4...660e0、モデルカード値と一致)をロード→`unknown model architecture: 'dory'`で失敗。
モデルカード案内の回避策(transformers本家mainからの再インストール、専用フォークllama.cppのビルド)は筆者の実行環境のセキュリティポリシーで試行不可、ローカル検証待ち。

https://huggingface.co/papers/2611.03998
