# Day 024 X投稿案: DietrichGebert/ponytail

## パターンA: 要点訴求型

```
コーディングAIに「怠惰なシニア開発者」を演じさせるClaude Code向けスキル ponytail を自分の環境で実測した。

既存コードで済むタスクでは差はゼロ。でも「新規UIが必要」なタスク(星レーティング追加)では、コード量が約68%減った。公式の「-53%」の方向性とは一致。

https://github.com/DietrichGebert/ponytail
```

## パターンB: 驚き訴求型

```
「1〜5の星で評価するフィールドを追加して」と頼んだら、片方は★アイコンのちゃんとしたUIを作り、もう片方は素のnumber inputを返してきた。

コード量は後者が68%少ない。でも「星」とは言われていない見た目になった。怠惰なシニア開発者、仕事は早いが聞いてないことは聞いてない。

https://github.com/DietrichGebert/ponytail
```

## パターンC: 技術者向け詳細型

```
ponytail(MIT, GitHub Trending上位)を検証。公式ベンチマークのclaude -p --plugin-dir方式はクラウド実行環境の権限制約でブロックされ再現不可だったため、同一モデル(Sonnet 5)への独立サブエージェント実行でルールセットを直接注入する簡易比較を自作。

・既存コンポーネント再利用が唯一解のタスク(日付/チェックボックス追加)→差ゼロ
・新規UIが必要なタスク(星レーティング)→ +28行 vs +9行(約68%減)、ただし見た目の要求(★UI)を素のnumber inputに置き換える副作用あり

詳細: 本リポジトリ experiments/day-024/
https://github.com/DietrichGebert/ponytail
```
