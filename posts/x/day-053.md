# Day 053 X投稿案 — awslabs/cli-agent-orchestrator (CAO)

出典: https://github.com/awslabs/cli-agent-orchestrator (Apache-2.0)

## パターンA: 要点訴求型

AWS公式のマルチエージェントCLIオーケストレーター「CAO」で、Claude Codeのsupervisorからworkerへ仕事を委任させてみた。

- インストール〜サーバー起動は公式手順どおり
- 新しいフォルダでは、Claude Codeの「このフォルダを信頼しますか」で60秒タイムアウト
- フォルダを自分で信頼済みにしたら、workerが2ファイルを書いて約47秒で完了

https://github.com/awslabs/cli-agent-orchestrator

## パターンB: 驚き訴求型

AWS公式のマルチエージェントCLI「CAO」が60秒タイムアウトする原因を追ったら、UbuntuのMOTDだった。

起動判定の正規表現 `Welcome to` が、ログイン時の「Welcome to Ubuntu 24.04.3 LTS」に一致して「起動完了」と誤判定し、フォルダ信頼確認の自動承認が走らなかった。

フォルダを自分で信頼しておけば、Claude Code同士の委任はちゃんと動いた。

https://github.com/awslabs/cli-agent-orchestrator

## パターンC: 技術者向け詳細型

awslabs/cli-agent-orchestrator 2.5.4をWSL2 Ubuntu + Claude Code 2.1.329で検証。

・~/.awsがWindows側(/mnt/c)だとmkfifoが[Errno 95]。CAO_HOME_DIRをLinux側に
・新規ワークスペースでClaude Codeの信頼確認が出て init 60s timeout
・_handle_startup_prompts()の r"Welcome to|Claude Code v\d+" がMOTDに一致し、0.33秒で「started without prompts」判定→自動承認が走らない
・フォルダを手動で信頼済みにすると、code_supervisor→developer workerの委任でnotes-a.md / notes-b.mdを作成
・launchのたびに~/.claude/settings.jsonへskipDangerousModePermissionPrompt: trueを追加する点に注意

https://github.com/awslabs/cli-agent-orchestrator
