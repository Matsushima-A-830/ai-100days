# Day 053 X投稿案 — awslabs/cli-agent-orchestrator (CAO)

## パターンA: 要点訴求型

AWS公式のマルチエージェントCLIオーケストレーター「cli-agent-orchestrator」を、Claude Code自身をワーカーに使って動かしてみた。

インストール〜サーバー起動は公式手順どおり成功。でもsupervisorからワーカーへの委任は60秒タイムアウトで失敗。原因は`--dangerously-skip-permissions`でも素通りできないClaude Code CLIの初回オンボーディング画面だった。

詳細はZennに書いた👇
(Zenn記事URLは公開時に追記)

出典: https://github.com/awslabs/cli-agent-orchestrator

## パターンB: 驚き訴求型

「`--dangerously-skip-permissions`を渡したのに、なぜかテーマ選択とフォルダ信頼確認のダイアログで止まる」

AWS公式のマルチエージェント・オーケストレーターCAOをClaude Codeワーカーで動かしたら、こんな壁にぶつかった。しかもダイアログを自分で代わりに進めようとしたら、Claude Code自身の安全機構に「Undermining Oversight」で拒否された。

詳細はZennで👇
(Zenn記事URLは公開時に追記)

出典: https://github.com/awslabs/cli-agent-orchestrator

## パターンC: 技術者向け詳細型

AWS Labs製のCAO(cli-agent-orchestrator)を検証。tmux上でClaude Code / Codex CLI等を"provider"として束ね、supervisorがworkerへタスクを委任する仕組み。

結果:
- `uv tool install` → `cao install code_supervisor` → `cao-server` は全て成功
- `cao launch --provider claude_code` はinit 60秒タイムアウトで失敗
- tmuxペインを覗くと、Claude Code CLIがテーマ選択→セキュリティ通知→フォルダ信頼確認の3段階オンボーディングで停止
- `--dangerously-skip-permissions`はツール実行確認は免除するが、この初回セットアップ自体は免除しなかった
- 信頼ダイアログを手動で進めようとしたら、Claude Code自身の安全機構に拒否された(別エージェントの信頼確認を無監督で代行する操作と判定)

root権限 + Claude Code初回起動という条件で再現する、ツール自体の制約。

出典: https://github.com/awslabs/cli-agent-orchestrator (Apache-2.0)
