## 1. 要点訴求型

TokenRouter(複数LLMをトークン単位でルーティングする推論サーバー)を検証しようとしたら、
ライセンスが未確定で記事化は断念。

でも検証の途中で踏んだ別の壁「最新GPU(Blackwell)だと動かない」は、
依存ライブラリのバージョンを差し替え、残った食い違いをソースパッチで越えられた。

出典: https://github.com/thu-nics/TokenRouter

## 2. 驚き訴求型

RTX 50シリーズでLLM推論サーバーを動かそうとしたら、

RuntimeError: RMSNorm failed with error code no kernel image is available

で撃沈。「GPUはあるのに動かない」という謎エラーの正体は、
依存ライブラリの事前コンパイル済みバイナリがBlackwell世代にまだ対応していないことだった。

新バージョンに差し替えたら今度は別のImportError。原因を1行ずつ追って、
使われていない機能のimportだけを先延ばしにするパッチを書いたら、ちゃんと推論が通った。

出典: https://github.com/thu-nics/TokenRouter

## 3. 技術者向け詳細型

sgl-kernel==0.3.8でRMSNorm failed(no kernel image, sm_120未対応)。
0.3.9〜0.3.18はtorch==2.8.0とABI互換を保ちつつBlackwellカーネルを追加済みと判明(二分探索で確認)。

ただし0.3.18+sglang==0.5.1では `ImportError: cannot import name 'fused_marlin_moe'`。
呼び出し箇所はawq.py/gptq.pyのMoE量子化メソッド内の2箇所のみで、bf16推論では未使用と判明。
import を try/except で遅延させる最小パッチで、Qwen3-0.6Bの実推論まで到達。

出典: https://github.com/thu-nics/TokenRouter
