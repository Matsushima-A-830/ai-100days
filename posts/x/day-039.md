# Day 039 X投稿案 — vercel-labs/agent-browser & agent-desktop

出典: https://github.com/vercel-labs/agent-browser / https://github.com/vercel-labs/agent-desktop (いずれもApache-2.0)

## パターンA: 要点訴求型

Vercel Labs製agent-browser(Apache-2.0)を試した。
スクショではなくアクセシビリティツリーを@refでAIエージェントに渡す方式。
実際にopen→snapshot→fill→clickで日本語フォームを操作できた。
ページサイズの文字数は素のHTML比で約48.6%削減(自分の簡易計測値)。
姉妹ツールagent-desktopはローカルPC(WSLg)でaccessibility権限はgrantedまで進んだが、GNOME前提のウィンドウ判定でACTION_NOT_SUPPORTEDに。

## パターンB: 驚き訴求型

「公式READMEどおりに`npm install agent-browser`したら、最新版じゃなく14バージョンも古いのが入った」
原因はNode 24未満だとengines要件でnpmが古いバージョンを選んでしまう仕様。
ローカルでNode22→24に切り替えて実際に再現/解消を確認。エラーも警告も出ないので誰でも気づかずハマりそう。

## パターンC: 技術者向け詳細型

agent-browser(Vercel Labs, Apache-2.0)検証メモ。
・`npm install agent-browser`(無指定)→内部的に`agent-browser@*`として解決→Node<24だとengines未達の新版が除外され旧版0.27.0が入る→`@latest`指定で回避
・snapshotは`@e1`形式のref付きアクセシビリティツリーをテキスト化、座標不要でclick/fillできる
・同一ローカルページで生HTML(1526字)vs snapshot出力(785字)=約48.6%減(公式の「Playwright MCP比90%減」とは比較対象が異なる参考値)
・ローカルPC(WSL2+WSLg)で同じコマンドをNode22/24双方で実行→22で旧版再現、24で最新版を確認
・agent-desktopはaccessibility権限がdenied→grantedに前進したが、list-apps/list-windowsは`ACTION_NOT_SUPPORTED`(`native_window_unproven`)。ツールのskillドキュメント曰くLinux版はGNOME前提、WSLgの実WMは`Weston WM`(xprop確認)で不一致
