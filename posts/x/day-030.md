# Day 030 X投稿案

対象: [heygen-com/hyperframes](https://github.com/heygen-com/hyperframes)(Apache-2.0、HTML/CSS/GSAPを確定的にMP4へレンダリングするOSS)。
検証: 自作GSAPアニメーションのMP4レンダリング、同じコマンドを3回実行してSHA256ハッシュを突き合わせた決定性検証、デフォルトテンプレートのCDN読み込み失敗とその回避。

## パターンA: 要点訴求型

HeyGen社がOSS公開した「hyperframes」で、HTML+CSS+GSAPのアニメーションを実際にMP4へレンダリングしてみた。

同じコンポジションを3回レンダリングして出力のSHA256を比較したら、3回ともバイト単位で完全一致。APIキー不要・GPU不要でここまで決定的な動画出力ができた。

https://github.com/heygen-com/hyperframes

## パターンB: 驚き訴求型

「同じ入力からは毎回同じMP4が出る」という売り文句、本当か試してみた。

```
$ sha256sum run1.mp4 run2.mp4 run3.mp4
3af0d4f...  run1.mp4
3af0d4f...  run2.mp4
3af0d4f...  run3.mp4
```

3回レンダリングしてSHA256が完全一致。2ワーカー並列キャプチャなのに非決定性ゼロだった。

https://github.com/heygen-com/hyperframes

## パターンC: 技術者向け詳細型

hyperframes(Apache-2.0)をnpx経由で実機検証。

- `npx hyperframes browser ensure`でChrome Headless Shell(113.9MB)を自動取得、`doctor`/`check`/`snapshot`/`render`は一通り動作
- デフォルトテンプレートは`cdn.jsdelivr.net`からGSAPを読む構成だが、`check`時に`net::ERR_TUNNEL_CONNECTION_FAILED`で失敗。ヘッドレスChromeサブプロセスがCDNへのトンネルを張れなかったとみられる
- `npm pack gsap`でライブラリを`vendor/`に同梱しローカル参照に切り替えて解消(ツール公式ドキュメントも「no network fetches」を推奨)
- 自作の3シーン(フェードイン→棒グラフ伸長→カウントアップ)を1920x1080/30fps/6秒でレンダリング。180フレーム・277,342 bytes
- 同一コマンドを3回実行し`sha256sum`で比較、3回ともハッシュ完全一致

https://github.com/heygen-com/hyperframes
