# Day 047 X投稿案 — lidge-jun/opencodex

出典: https://github.com/lidge-jun/opencodex (MIT)

## パターンA: 要点訴求型

Codex/Claude Code向けのプロバイダープロキシ「opencodex」を、手元のOllama+Qwen2.5-32B(このPCで載る最大サイズ)で試した。

- Anthropic / OpenAI Chat / OpenAI Responses の3形式すべてで変換成功
- ストリーミングもツール呼び出し(tool_use→tool_result)も往復で動いた
- プロキシを挟んだ遅延は測定誤差の範囲

https://github.com/lidge-jun/opencodex

## パターンB: 驚き訴求型

opencodex経由でAnthropic形式のリクエストをローカルのQwen2.5-32Bに送ったら、返ってきた応答の model 欄が

"the requested model"

原因は、モデル名チェックの正規表現が「:」を許していないこと。
Ollamaのモデル名は qwen2.5:32b-instruct みたいに必ず「:」が入るので、ほぼ確実に踏む。

変換そのものはツール呼び出しまで完璧に動いていた。

https://github.com/lidge-jun/opencodex

## パターンC: 技術者向け詳細型

opencodex v2.100.2(MIT)を Ollama 0.35.1 + qwen2.5:32b-instruct(21GB, 30%/70% CPU/GPU, RTX 5060 Ti 16GB)で検証。

・/v1/messages, /v1/chat/completions, /v1/responses 全て200。Anthropic側usageはcached_tokensがcache_read_input_tokensに振り分けられる
・stream:true → message_start/content_block_delta/…/message_stop の正規SSE
・Anthropic tool_use→tool_result往復、Responses function_call もOK
・直接 vs 経由 3回ずつ: 5.2〜5.7s で差なし

注意: Anthropic応答のmodelが "the requested model" になる(clientModelIdの正規表現が":"不許可)。あと ocx start は既定で api.anthropic.com 向けのintercept proxyも立てるので、Claude Code常用PCでは HOME を分けて試した。

https://github.com/lidge-jun/opencodex
