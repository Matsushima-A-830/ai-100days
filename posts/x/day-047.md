# Day 047 X投稿案 — lidge-jun/opencodex

出典: https://github.com/lidge-jun/opencodex (MIT)

## パターンA: 要点訴求型

Codex/Claude Code向けのプロバイダープロキシ「opencodex」を試した。
Anthropic Messages / OpenAI Chat Completions / OpenAI Responses、3つのAPI形式を1つのバックエンドに変換・転送できるか確認。

- npm install -g だけで導入完了
- 最初はストリーミング非対応で502
- SSE対応にしたら3形式すべて200で変換成功

https://github.com/lidge-jun/opencodex

## パターンB: 驚き訴求型

Anthropic形式のリクエストを送ったのに、裏では黙って`"stream":true`が付いてOpenAI形式でバックエンドに転送されていた。

opencodex(Codex/Claude Code向けプロバイダープロキシ)の中継を覗いたら、ストリーミング非対応の自作モックサーバーは一発で502。
SSE対応に直したら、Anthropic/OpenAI Chat Completions/OpenAI Responsesの3形式すべてで変換に成功した。

https://github.com/lidge-jun/opencodex

## パターンC: 技術者向け詳細型

opencodex v2.100.2(MIT)を検証。`ocx provider add --adapter openai-chat --base-url http://localhost:11434/v1`でカスタムプロバイダを登録、`ocx start`でlocalhost:10100にプロキシが立つ。

実機OllamaはRoutine環境のネットワーク制約で使えなかったため、同ポートに`/v1/chat/completions`だけ実装した自作モックで代替。
`POST /v1/messages`(Anthropic)・`/v1/chat/completions`(OpenAI)・`/v1/responses`(OpenAI Responses)の3エンドポイント全てで200、応答も各形式に正しく変換されていた。
初回は非ストリーミング応答で502→SSE対応で解決。

https://github.com/lidge-jun/opencodex
