# 怠惰なシニア開発者に仕事を頼んでみた

## きっかけ

GitHub Trendingを眺めていたら、ponytailというプラグインが目に入った。コーディングAIに「最も怠惰なシニア開発者」を演じさせ、新しいコードを書く前に既存コード・標準ライブラリの再利用を優先させるというもの。公式は「コード行数-53%・トークン-45%・コスト-26%」という強烈な数字を掲げていて、同時に「独立検証では数字が小さく出ることもある」という話も目にしていたので、自分の手で確かめたくなった。

公式のやり方はシンプルで、Claude Codeを`claude -p`でヘッドレスに起動し、スキルを読み込ませた版と読み込ませない版を比較するだけだ。同じことを自分の検証環境でもやろうとした。

## 葛藤・失敗

ところが、そのコマンドを打った瞬間に止められた。「Create Unsafe Agents」という理由で、権限を昇格させた入れ子のエージェントを起動する操作そのものが、安全機構によってブロックされたのだ。許可モードを変えて何度か試したが、同じ理由で跳ねられる。これはponytailのバグではなく、自分が今回使っている実行環境側の制約だとすぐに分かった。公式と全く同じ方法での検証は、ひとまず別の環境に持ち越すしかなかった。

そこで方針を変え、同じモデルに対して「何も指示しない版」と「ponytailのルールセットをそのまま読ませた版」を、別々の独立した実行コンテキストで走らせて比較する、という代替手段を自分で組み立てた。公式の方法とは違うので、鵜呑みにはできない結果になることは承知の上で、まずは手を動かしてみることにした。

最初に試した2つのタスク(生年月日フィールドの追加、チェックボックスの追加)は、拍子抜けするほど差が出なかった。どちらのバージョンも、既存の汎用コンポーネントに1行足すだけの、全く同じコードに落ち着いたのだ。「あれ、何も効いていないのでは」と一瞬思ったが、公式のベンチマーク資料を読み直すと、そもそも効果を測るタスクは「まだ存在しない機能」を選ぶべきだと書かれていた。自分が用意したタスクは、再利用する以外の選択肢がほとんど無い、比較には向かないタスクだったのだ。

## 学び・気づき

公式のタスク一覧にあった「星レーティングを追加する」というタスクを真似て試し直すと、ようやく差が見えた。何も指示しなかった版は、★アイコンを並べたそれなりに本格的なUIコンポーネントを新しく書いた。一方、ルールセットを読んだ版は、既存の入力ヘルパーに最小限の属性を足すだけで済ませ、コード量はおよそ3分の1になった。方向性としては公式の主張と一致している。

ただ、その内容をよく見ると、少し引っかかるものがあった。ルールセットを読んだ版が作ったのは、見た目が普通の数値入力欄で、★の形は一切していなかった。タスクには「星で評価する」と書いてあったのに、その見た目の要求には応えていなかったのだ。コードが安全で正しく動くことと、頼んだ通りのものが出てくることは、必ずしも同じではないらしい。

「コードを減らす」という指示は強力に効く一方で、何も言っていない部分まで勝手に削ぎ落としてしまうことがある、という当たり前のようで見落としがちな点を、実際に手を動かして初めて実感できた。数字だけを見て「すごい、53%減った」と驚くのと、実際に生成されたものを一つひとつ開いて確かめるのとでは、見えてくるものが違う。
