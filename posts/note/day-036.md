# Day 036 note原稿

要点3行:
- GPUなし(CPU 4コア)の環境で、LLMの拒否挙動をOptunaの最適化で外す「Heretic」を実際に動かした。
- Qwen3-0.6Bの拒否率はベースライン2/10から、2回の試行とも0/10まで下がった。
- デフォルト設定(試行100回)をこの環境で完走させると、実測値からの推定で約25時間かかる計算になった。

---

GitHub Trendingで見かけた「Heretic」というツールが気になった。
LLMの「拒否挙動」、つまり安全性のために設定された検閲のようなふるまいを、再学習なしで外せるという。
しかもOptunaというパラメータ探索の仕組みを使って、拒否率と「元のモデルからどれだけ出力がズレたか」を同時に最小化するように、自動で最適なパラメータを探してくれるらしい。

今日のお題はこれに決めた。
ただ、READMEを読むとRTX 3090での実行時間しか書かれていない。
筆者のクラウド実行環境にはGPUが一切ない。
「GPUがないと動かないツールなのか、それとも遅いだけで動くのか」がまずわからなかった。

とりあえず動かしてみることにした。
インストールの時点で一度詰まった。
`pip install -U heretic-llm`を素直に叩くと、依存関係に含まれる古いパッケージのビルドでエラーが出た。
これはHeretic自体のバグというよりシステム側のPython環境との相性問題で、仮想環境(venv)を作ってやり直すとすぐに解決した。
小さなことだが、「公式のコマンドをそのまま叩いただけでは動かない」という経験は、今日みたいに手を動かして初めて出てくる。

次の葛藤は「どう縮小するか」だった。
デフォルトの設定は、試行回数100回・評価用のプロンプトも100件単位というかなりの規模で、GPUなしでそのまま回したら日が暮れても終わらないだろうことは想像がついた。
作業時間は6時間という目安がある。
そこで試行回数を2回、評価用のプロンプトを10件まで減らした「ごく小さいスモーク実行」に切り替えることにした。
縮小しすぎて何も確認できないのでは、という不安はあったが、まずは実際に動かして数字を見てから判断しようと決めた。

結果として、これは思ったよりうまくいった。
Qwen3という小さなモデル(0.6B)に対し、改変前は10件のうち2件が拒否ワードを含む応答をしていたのが、2回の試行とも0件になった。
しかも2回目の試行は、1回目よりも「元のモデルからのズレ」を示す数値(KL発散)が3分の1程度に小さく、さらに実行時間も短かった。
Optunaはわずか2回の探索でも、ちゃんとより良い方を選び出していたことになる。
「拒否挙動は内部のある1つの方向を操作するだけで抑制できる」という理論を、自分の手で、しかもGPUなしの環境でも数字として確かめられたのは、今日いちばんの収穫だった。

一方で、今回縮小した設定から逆算すると、デフォルトの試行100回をこの環境でそのまま完走させるには、ざっと25時間はかかる計算になった。
RTX 3090での参考値(30〜40分)と比べると40倍近い。
GPUの有無でこれだけ差が出るという感覚を、推測ではなく実測からの外挿として持てたのも大きかった。
「動かないから諦める」のではなく「どこまで縮小すれば動くか」を試すことで、ツールの仕組みそのものは確認できる、というやり方を今日は選んだ。
