## 要点3行

- Claude Codeを49エージェントの「ゲーム開発スタジオ」に変えるOSSテンプレートを、クラウドの実行環境がブロックして動かせなかったため、手元のPCで改めて最初から動かし直した
- 衛星リレー局を修理するゲーム「Signal Lost」を実際に1本、`/start`から`/dev-story`まで通して作り、最後は遊べるところまで到達した
- 途中、WSLとUnityの相性という想定外の壁と、Unityのドメインリロードが絡む地味で厄介なバグに足止めされた

---

今日選んだネタは、Claude Codeのサブエージェント・スキル・フックだけで49体のゲーム開発スタジオを組み上げるテンプレート「Claude Code Game Studios」だった。このリポジトリ自体がClaude Code Routineで運用されているので、Claude Codeで動くテンプレートをClaude Codeで検証する、という入れ子の構図になる。面白そうだと思って選んだ。

朝のRoutineでは、肝心の`/start`実行がうまくいかなかった。クローンしたテンプレートのディレクトリで`claude -p "/start"`を動かそうとしても、自動実行されるクラウド環境側の安全策に「外部コードだから」という理由で止められてしまう。README記載の数字(49エージェントなど)をファイル数で裏取りするところまではできたが、肝心のワークフローは動かせないまま、ローカルでの再検証に持ち越すことにした。

そこで夜、手元のPCで改めてクローンし直し、対話的なセッションで`/start`から動かしてみた。「アイデアなし」と答えると`/brainstorm`に誘導され、提示された3つの案から「衛星リレー局をデブリ場から部品を集めて修理し、軌道が崩壊する前に復旧させる」というゲームを選んだ。`/setup-engine`はUnity経験があると答えると即座にUnityに決まり、しかも手元に実際にインストールされているバージョンをPowerShellで直接調べにいって、最新版との差分まで検出してきた。ここまでは思っていたより滑らかだった。

詰まったのはここからだった。`/create-stories`と`/dev-story`で6本のストーリーをサブエージェントに実装させ、いざUnityプロジェクトを作ろうとしたら、「大文字小文字を区別するファイルシステムには対応していない」という理由でUnityエディタに拒否された。作業リポジトリがWSL(WindowsのLinux環境)上にあったのが原因だった。これはテンプレートの不具合ではなく、自分の開発環境の組み合わせが悪かっただけなのだが、ここで一度手が止まった。結局、Unityプロジェクト本体だけWindows側の別の場所に作り直し、コードは手動でコピーして同期する、という運用に切り替えてしのいだ。

ようやくコンパイルが通り、安心したのも束の間、今度は実際に動かして遊べるようにする段階で別の壁にぶつかった。画面にプレイヤー以外何も映らない。カメラの設定を直してもまだ何も映らない。デバッグログを1行ずつ足して原因を追っていくと、エディタのメニュー操作で生成したスプライト(四角い見た目)への参照が、Playモードに入った瞬間に消えていることがわかった。一方で、プログラムの実行中に生成したスプライトは問題なく表示されている。同じ「一時的に生成したオブジェクト」でも、いつ作ったかによって生き残るかどうかが違う。これに気づくまで、かなり遠回りをした。

これらを一つずつ潰していって、最後にプレイヤーを動かしてデブリをスキャンし、部品を回収し、ステーションで修理する、という一連の操作が実際に成立した瞬間は、素直に嬉しかった。全部直せば勝利画面、直しきれなければ敗北画面が、ちゃんと出る。

このテンプレートが掲げている「パースが通ることと、実際に動くことは別物」という検証姿勢は、今日まさにその通りだと実感した。コードがコンパイルを通っても、遊べる状態になるまでには、結局いつも通り、人間の目で画面を見て、ログを足して、少しずつ原因を切り分けていく作業が必要だった。49体のエージェントがいても、最後の「動かしてみて、何かおかしいときに気づく」部分だけは、今日もこちらの役目のままだった。
