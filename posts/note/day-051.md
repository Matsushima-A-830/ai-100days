# Day 051 note原稿 — 「2時間で自作LLM」を手元のGPUで公式どおり回した話

要点3行:
- GitHub Trendingで話題の「2時間で自作LLM」を掲げるOSS minimindを、手元のRTX 5060 Tiで公式の手順・データ・既定値のまま最後まで回した。
- 結果はPretrain 2時間42分+SFT 4時間37分の合計7時間19分で、公式のRTX 3090目安(約2.3時間)の約3.2倍かかった。
- 学習後のモデルは自己紹介や箇条書きの「形式」は身につけたが、知識を問う質問の中身は不正確なままだった。

---

今日調べていたのは、GitHub Trendingで急上昇していたminimindというプロジェクトだった。
「RMB 3・2時間でLLMをゼロから作れる」という売り文句と、65,881スターという数字が目についた。
64Mパラメータという小さなモデルとはいえ、学習パイプライン全体を自分の手元で最初から最後まで回せるなら、試す価値があると思った。

最初は、データを公式の0.4〜0.5%まで削った縮小版で、CPU 4コアだけでPretrainとSFTを回した。
約1時間40分で最後まで動き、lossも下がった。
ただ、これで分かるのは「パイプラインが動く」ということまでで、「2時間で作れる」という主張そのものは確かめられていない。
それなら手元のGPUで、公式の手順どおりに回してみようと考えた。

方針は単純で、モデル構成もスクリプトの既定値も変えず、公式のmini版データセットを全量使う。
変えたのは、公式の目安に合わせて学習を1周(1 epoch)にする指定だけにした。
「mini」と名付けられたデータでも、Pretrain用が約127万行、SFT用が約91万行あった。

縮小データを同じGPUで回すと、CPUで約1時間40分かかった学習が約3分10秒で終わった。
lossの下がり方はCPUのときとほぼ同じで、違うのは速さだけだった。
この速さなら全量でも数時間で終わりそうだと期待した。

ところが全量のPretrainは、2時間42分かかった。
公式の3090目安は約1.21時間なので、Pretrainだけで約2.2倍である。
lossは7.52から2.01まで下がり、ここまでは順調だった。

途中で一度つまずいたこともあった。
縮小版の重みを全量学習の重みと混ぜたくなかったので、保存先を別のフォルダに指定してSFTを始めたところ、「`../out/pretrain_768.pth`が見つからない」というエラーで止まった。
コードを読むと、SFTスクリプトは保存先の指定に関係なく、常に決まったフォルダからPretrainの重みを読み込む作りになっていた。
公式どおりのフォルダを使っていれば起きない問題だが、手順を少し変えるとこういうところで引っかかる。

SFTは4時間37分かかった。
こちらは公式の目安の約4.2倍で、Pretrainよりも差が大きかった。
合計すると7時間19分で、夜に始めた学習が終わったのは日付をまたいだ深夜3時過ぎだった。
同じスクリプト・同じデータでも、GPUが変われば「2時間」は「半日近く」になる。
公式の数字は、RTX 3090クラスのGPUがあるという条件付きで読むべきものだと分かった。

学習を終えたモデルに「あなたの得意なことは？」と聞くと、「私はMiniMind、jingyaogongが作った効率的なAIモデルです」と、名前まで入った自己紹介で答えた。
光合成の仕組みを聞くと、見出し付きの箇条書きで答えようとする。
形式はちゃんとSFTのデータから学んでいた。
ただ中身を読むと、光反応を「原子核反応」と説明していて、内容は正しくなかった。
64Mパラメータを1周学習させただけのモデルでは、答え方の形は身についても、知識の正確さまでは届かない。

振り返ると、今日いちばん大きかったのは、READMEに書かれた「2時間」を自分のGPUで実際に測ってみたことだった。
数字そのものは公式の3倍以上になったが、64MのLLMをゼロから学習させて、チャット形式で答えるところまでを一般的なゲーミングGPU 1枚で一晩のうちに終えられた。
公式の主張が「どの条件でなら成り立つのか」を、自分の環境の数字で確かめられたのが今日の収穫だった。
