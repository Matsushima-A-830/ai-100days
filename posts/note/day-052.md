# Day 052 note原稿 — LLMに重みを「書かせる」論文を手元で再現した話

要点3行:
- 勾配降下を使わずLLMにモデルの重みを直接書かせる「Weight-Space Programming」を、論文の公開ハーネスで手元のPCから再現した。
- Claude Opus 5.5がARCの例題10問だけから理科の事実4,071行と検索手順を書き、テスト正解率50.79%(論文の第1世代は50.8%)になった。
- 動かすまでにサンドボックス周りで3回止まり、最後はClaudeプランの5時間上限で止まったが、それも含めて手元で確かめる意味を感じた。

---

## きっかけ

Weight-Space Programmingという論文を見つけたとき、まず引かれたのは「LLMに重みを書かせる」という言葉そのものだった。
モデルの重みはふつう勾配降下法で少しずつ更新していくもので、誰かが値を書き込むという発想は聞いたことがなかった。

公開コードには、Claude Code CLIをサンドボックスの中で「writer」として起動し、書かせたモデルを採点するまでを一括で行うハーネスが入っていた。
論文の数字はこのハーネスで出したものなので、同じハーネスを自分のPCで動かせば、論文の主張をそのまま確かめられると考えた。

## 葛藤・失敗

最初に、ハーネスを通さずにClaude Codeへ同じタスク文を渡し、モデルを書かせてみた。
155個の事実文を単語の重なりで検索するだけの小さなモデルで、テスト正解率は31.33%だった。
chanceの25%は超えているが、論文の50%台とは大きな差がある。
この差が「書かせ方」の違いなのか、別の理由なのかは、ハーネスを動かしてみないと分からなかった。

ところが、そのハーネスがなかなか動かなかった。
1回目は、隔離実行の中でpythonが見つからないと言われた。
調べると、サンドボックスが`/tmp`を空の領域で覆う作りになっていて、`/tmp`の下に置いていたPython環境ごと見えなくなっていた。
2回目は、通信用のソケットのパスが長すぎるというエラーだった。
3回目は、Python環境をホームディレクトリの下に移したところ、「サンドボックスからホームディレクトリが見えている」という安全チェックに引っかかった。
このチェックは、writerが採点用データや手元のファイルを覗けないことを保証するためのものなので、チェックを外すのではなく、置き場所を変えることにした。
最終的に、全部を`/opt`の下に置いて通った。

## 学び・気づき

動き出したOpusは、約45分かけて理科の事実を4,071行書き出し、表記ゆれをまとめる処理や、否定を含む選択肢の扱いまで、分岐なしのテンソル演算だけで組み上げた。
テスト3,530問の正解率は50.79%で、論文の第1世代の50.8%とほぼ同じだった。
同梱されている論文のモデルを採点し直しても50.80%で、保存された結果と一致した。

もう一つ分かったのは、最初に書かせた小さなモデルとの差の理由だった。
どちらも練習問題を使った試行は0回で、違いは書いた知識の量と、それを読む手順の作り込みだった。
ハーネスの中のwriterは、自分で確認用の問題を作ってはモデルを直すことを、出力25万トークン分ほど続けていた。

ただ、その作業は最後までは終わらなかった。
途中でClaudeプランの5時間あたりの利用上限に達して止まり、ハーネスはその時点のモデルを採点した。
それでも論文とほぼ同じ数字になったが、1回の実行がそれだけの量を使うことは、手元で動かしてみて初めて実感した。

論文の表にある数字を読むだけでなく、同じハーネスを自分の環境で動かすと、数字そのものに加えて、どこでつまずき、どれだけの計算を使うのかまで見えてくる。
それが今日いちばんの収穫だった。
