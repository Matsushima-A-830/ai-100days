# メモリ(要約)条件: Project Nova

`transcripts/project_nova.md` の3セッションを読んだ後に構築した、現実的な「メモリシステム」
が持っていそうな要約状態。設計方針は以下の通りで、質問セット(`questions.md`)に逆算して
都合よく作ったものではない(先に方針を決め、その方針に沿って何を残し何を残さないかを判断した)。

**設計方針:**
- 「現在値(current state)」は常に最新の値で上書きする(典型的なメモリシステムの振る舞い)。
- 計画会議の中で明示的に「変更する/確定する/上方修正する」等と言及された**主要な意思決定**
  (技術スタック・予算・締め切り・チーム構成)については、変遷を追えるよう簡単な
  **変更履歴(changelog)**も残す。これは「重要な決定と経緯を記録する」よう設計された
  要約メモリでは自然に行われる処理だと考えられる。
- 一方、計画上の意思決定として明示的に議論されたわけではない**付随的な設備・インフラの
  細部**(ステージング環境のサーバー機種など)は、現在値のみを残し、過去の値は上書きで
  失われる。これは「重要でない雑談・細部は捨てる」という要約メモリの典型的な振る舞いを
  模したもの。
