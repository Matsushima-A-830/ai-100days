## ローカル検証(人間のPC、2026-11-10)

検証環境: WSL2(Ubuntu 24.04)、Python 3.12.3、venv、リポジトリHEAD `15c7cdc`。
LLM認証情報はGemini無料枠キーではなく、人間のPCに既に導入済みのローカルOllama
(`qwen2.5:7b-instruct`、無料枠APIキー不要)を使った(`.env`に
`OLLAMA_API_BASE=http://localhost:11434` / `LITELLM_MODEL=ollama/qwen2.5:7b-instruct` を設定)。

### 1. Routine環境の3つの制約は、いずれもローカルでは再現しなかった

- **ネットワーク到達性**: Yahoo Finance(429=レート制限であって403ブロックではない)、Baostock(200)、
  東方財富(404=ルートパスが存在しないだけで到達はしている)、新浪財経(403=サイト側のアンチボット挙動)
  と、いずれも実際のサーバー応答が返ってきており、Routine環境で見られた
  `CONNECT tunnel failed, response 403`(プロキシ層でのブロック)とは明確に異なる。
- **LLM認証情報**: ローカルOllamaをそのまま使え、追加のAPIキー取得は不要だった。
- **コード実行権限**: `python -m pytest -m "not network"` がRoutine環境では拒否されていたが、
  ローカルでは何の制約もなく実行できた。結果は **8,476 passed, 4 deselected, 735.24秒(約12分15秒)**。
  全件パスし、リポジトリ自体のオフライン単体テストは健全だった。

### 2. `--dry-run` はデータ取得のみでLLM呼び出しなし、という説明は正確ではなかった

```bash
python main.py --dry-run --stocks 7203.T,600519,AAPL
```

ログを見ると、**個別銘柄のAI分析は確かにスキップされていた**
(`[AAPL] 跳过 AI 分析（dry-run 模式）` 等)。
一方で、`--dry-run` を付けても**「大盘复盘」(市場全体のレビュー)機能は実行され、
実際にOllama経由でLLM呼び出しが行われ、984文字のレビュー文章が生成されて
`reports/market_review_20261110.md` に保存された**。README・`--help`の「dry-runはデータ取得のみ」
という説明からは想定しにくい挙動で、個別銘柄分析と大盘复盘で`--dry-run`の扱いが異なる、という
実際の挙動として記録しておく。

データ取得自体は実際に成功した。日本株(7203.T)・米国株(AAPL)はYfinanceFetcherへ、
中国株(600519)はEfinanceFetcher(東方財富のK線API)へと、市場ごとに適切なデータソースへ
自動的にルーティングされ、いずれも実在する直近の株価データ(例: 600519の直近3営業日の終値
1453.00/1444.99/1439.00元など)を取得できていることを確認した。

### 3. 市場全体の統計が全滅すると、レビュー文章は「データが無い」ことを明示せず「0」として扱われる

大盘复盘のログを追うと、市場全体の騰落銘柄数・出来高統計(`get_market_stats`)の取得で、
東方財富(JSONパースエラー)・Akshare(2つのAPIでいずれも30秒タイムアウト)・Pytdx/Baostock/Yfinance/Tencent
(いずれも対応データなしで即座に空)と、**用意された6つのデータソース全てが失敗・空振りに終わった**
(ここだけで66秒超を消費している)。

```
[MarketStats] ... action=complete status=empty purpose=market_review:cn
```

にもかかわらず、生成された`market_review_20261110.md`には「涨跌家数为零，涨停与跌停个股也均为零」
「今日市场成交额为0亿元，成交极度低迷」と、**データが取得できなかった結果の「0」を、
あたかも実際の市場統計であるかのように断定的な文章で説明していた**。LLM(Ollama経由の
qwen2.5:7b-instruct)に渡されたプロンプト自体が「0」という具体的な数値しか渡しておらず、
「データ取得失敗」という文脈を渡していなかったためと考えられる。株価・金融情報を扱うツールとして、
この種の「取得失敗の0」と「本当の0」を区別できない挙動は、読者が実際に使う際に注意すべき点として
記録しておく。

### 4. 本実行(LLM判定込み)は3銘柄とも完走したが、ローカルモデルではJSON検証エラーが頻発した

```bash
python main.py --stocks 7203.T,600519,AAPL
```

パイプラインのサマリーは **「成功: 3, 失败: 0, 耗时: 58.13 秒」** で、3銘柄とも処理自体は完走し、
決定ダッシュボード`reports/report_20261110.md`が生成された。ただしログを見ると、
LLMの応答が期待するJSONスキーマに一致しない事象が複数回発生していた。

```
[LiteLLM] ollama/qwen2.5:7b-instruct failed: invalid_json at validation for backend litellm
[LLM JSON] 贵州茅台(600519): all models returned invalid JSON, using text fallback
...
AnalysisReportSchema validation failed; continuing with raw parser contract: 2 validation errors
[LLM完整性] 必填字段缺失 [...]，已占位补全，不阻塞流程
```

ツール側にリトライ・プレースホルダー補完というフォールバック機構があるおかげでパイプライン自体は
止まらず「成功」として扱われるが、実際に生成されたダッシュボードの中身を見ると、3銘柄のうち2銘柄
(7203.T・600519)の「一句话決策」は具体的な理由を欠いた「分析完成」という汎用文言のままで、
「止损位」(損切りライン)も「待补充」(未補完)のままだった。AAPLだけは「持有观察：市场资金流服务
暂不支持，买入结论缺少资金面确认，先按观察处理。」という具体的な一文が生成されていた。
3銘柄とも最終的な評点は揃って「评分 50・持有・震荡」という同一の結果になっており、Gemini等の
より高性能なモデルを使った場合と比べて、ローカルの7Bモデルではスキーマ適合率・判定内容の
具体性が下がる可能性がある、という実際の挙動として記録しておく。

一方で、各銘柄のダッシュボードには「数据限制: 量能数据缺失、筹码结构数据缺失、quote: fallback、
technical: partial」のように、どのデータが欠けているかを明示する欄があり、個別銘柄レベルでは
データ欠損を隠さず開示する設計になっていた(3節の大盘复盘とは対照的)。

### 5. 本実行後の2回目の大盘复盘生成が、Ollama自体は正常なまま9分以上応答なしで止まった

本実行(`--stocks`指定、dry-runなし)では銘柄分析完了後に大盘复盘も再度実行される。1回目の
dry-run実行時には大盘复盘のLLM生成は19秒で完了していたが、本実行での2回目の生成は、
セクター/コンセプトランキング取得(今回はキャッシュ利用で数秒に短縮)の後、LLM呼び出しの
段階で進行が止まり、600秒のタイムアウトで強制終了されるまで応答が返らなかった。
Ollama自体が無応答になっていたわけではないことは、別途 `curl .../api/generate` で
同時に動作確認が取れたことから確認済み(0.24秒で応答)。原因はOllama自体の不調ではなく、
大盘复盘パス側のリトライ/検証ロジックか、同一セッション内で2回目のLLM呼び出しを行う際の
何らかの資源競合によるものと推測されるが、ソースコードまでは追い切れておらず断定はできない。
再現性のある挙動として記録するにとどめる。

### まとめ

- Routine環境が報告した3つの制約(ネットワーク・LLM認証・コード実行権限)は、いずれもローカルでは
  再現せず、Routine実行環境固有の制約だったことを裏付けた。オフラインテストは8,476件全てパスした。
- `--dry-run`は個別銘柄のAI分析はスキップするが、大盘复盘(市場レビュー)のLLM呼び出しはスキップ
  しない、という文書の説明と異なる実際の挙動を確認した。
- 大盘复盘機能は、市場全体の統計データソースが全滅した際、取得失敗を「0」としてLLMに渡してしまい、
  生成文章がそれを実際の市場統計であるかのように断定的に説明する、という信頼性上の懸念を実際に確認した。
- 本実行(LLM判定込み)は3銘柄とも完走し、実際の決定ダッシュボードが生成されたが、ローカルの
  7Bモデルでは出力JSONのスキーマ検証エラーが頻発し、3銘柄中2銘柄は具体的な分析内容を欠いた
  プレースホルダー(「分析完成」「待补充」)のまま出力された。
- 本実行後の2回目の大盘复盘生成が、Ollama自体は正常なまま9分以上応答なしで止まり、
  全体のタイムアウトで強制終了されるという再現性のある挙動も観測した。
- 本ツールが出すすべての判定(買い/様子見/売り、評分、止损位等)は、本検証を含めあくまで
  技術的な動作確認であり、投資助言ではない。
